# Compliance

One row per MUST / SHOULD / MAY in each in-scope RFC (AGENTS.md §6).

- **Level**: MUST, SHOULD or MAY as written in the RFC (MUST NOT and SHOULD
  NOT count as MUST and SHOULD). `info` marks a rule from text without
  requirement key words, such as the informational RFC 6483, that the
  implementation follows.
- **Status**: `done`, `partial`, `todo`, `n/a`, or `deviates` (with a reason).
- **Code** / **Test**: file paths, `path:line` where useful. `wire/` is
  `crates/bgpfc-wire/src/`, `fsm/` is `crates/bgpfc-fsm/src/`, "fsm
  tests" are `crates/bgpfc-fsm/src/machine/tests.rs`, `bgpfcd/` is
  `crates/bgpfcd/src/`, `config/` is `crates/bgpfc-config/src/`
  ("config golden" is `crates/bgpfc-config/tests/golden/`), `rib/` is
  `crates/bgpfc-rib/src/` ("rib tests" are `crates/bgpfc-rib/src/tests.rs`,
  "rib enforcement tests" `crates/bgpfc-rib/src/tests/validation/enforcement.rs`,
  "rib nexthop tests" `crates/bgpfc-rib/src/tests/nexthop.rs`,
  and "rib decision.rs" and "rib order.rs" the property tests in
  `crates/bgpfc-rib/tests/`),
  `policy/` is `crates/bgpfc-policy/src/` ("policy tests" are
  `crates/bgpfc-policy/src/tests.rs`), `fib/` is `crates/bgpfc-fib/src/`,
  `sys/` is `crates/bgpfc-sys/src/`, `rpki/` is `crates/bgpfc-rpki/src/`
  ("rpki properties" are `crates/bgpfc-rpki/tests/properties.rs`), `rtr/`
  is `crates/bgpfc-rtr/src/` ("rtr session tests" are
  `crates/bgpfc-rtr/src/session/tests.rs`, "rtr client tests"
  `crates/bgpfc-rtr/src/client/tests.rs`), `sidecar/` is
  `crates/bgpfc-sidecar/src/`, "interop" names a test in
  `interop/tests/bird.rs`, "interop rpki" one in `interop/tests/rpki.rs`,
  "interop sidecar" one in `interop/tests/sidecar.rs`, "interop
  routinator" one in `interop/tests/routinator.rs`, and "interop
  multihop" one in `interop/tests/multihop.rs`.

The README must not claim compliance with an RFC until every MUST row for it
is `done`.

## RFC 6811 / 8481 / 6483 / 9319 — BGP prefix origin validation

Every route the Adj-RIBs-In hold is validated on arrival and again when the
validation source changes, and its state is kept on the route and shown by
the control plane. Without an `rpki` block, or with `mode disabled`, every
route is `disabled`; with `mode external` the VRPs come from RTR caches, and
with `mode sidecar` from a Routinator that bgpfcd runs and connects to on
loopback (the RFC 8210 section below). Until the first full set arrives
every route is `disabled` in those modes too, and used, or held with
`startup hold`: the startup window of `docs/config.md`, which with the
sidecar lasts Routinator's first validation run. Two things act on the
state, both configured. The
`rpki` block's `enforcement`: `drop-invalid`, the default, holds Invalid
routes in the Adj-RIB-In out of route selection, so they are neither
installed nor advertised; `prefer-valid` drops nothing and ranks Valid over
NotFound over Invalid before `LOCAL_PREF`; `off` leaves the state to policy.
And policy: `match rpki` in any policy, and `set rpki` in import policies,
which sets the state the route is used with while the looked-up one is kept.
A route held for its state stays in the Adj-RIB-In, whatever its state, and
is used again without an UPDATE once its state, the `enforcement` or the
`startup` allows.
RFC 8481 clarifies RFC 6811; its rows follow those of RFC 6811.

## RFC 8210 / 6810 — The RPKI-to-Router protocol

bgpfcd takes its VRPs over RTR from the caches of `rpki { mode external;
... }` (`docs/config.md`, "RPKI"), or from the Routinator that `rpki { mode
sidecar; }` has it run (`sidecar/`, started and wired by
`bgpfcd/rpki.rs`), offering version 1 (RFC 8210) and falling back to
version 0 (RFC 6810). Only the router's side is
implemented, so the rows below leave out what RFC 8210 asks of caches. The
session machine (`rtr/session.rs`) is pure, with time injected; the client
thread (`rtr/client.rs`) is its I/O shell, and bgpfcd runs it
(`bgpfcd/rpki.rs`). The unprotected TCP transport is the only one (AGENTS.md
§4). The interop tests run bgpfcd against StayRTR, an independent cache,
and against a stub cache of their own (`interop/src/bin/rtr-stub.rs`) for
a cache that restarts and answers bgpfcd again, which StayRTR 0.5.1 does
not (see the §8.1 row). The sidecar's run against a fake Routinator that
serves RTR with that stub cache (`interop/tests/sidecar.rs`), which can be
made to fail, hang or change its version, and once against the real
Routinator 0.15 (`interop/tests/routinator.rs`), with no network, on an
RPKI repository the test signs and serves itself (AGENTS.md §5).
